# 01 · 自动化评测引擎设计说明（Python & API）

> 状态：已完成 ✅ ｜ 自检：21/21 通过 ｜ 覆盖：并发调用、断点重试、强约束解析、成本与延迟度量

## 1. 模块划分

| 文件 | 职责 | 关键设计 |
|---|---|---|
| `src/core/client.py` | LLM API 客户端 | OpenAI 兼容 REST；指数退避重试（仅对超时/429/5xx 重试，4xx 快速失败）；Token 与成本统计；Mock 模式 |
| `src/core/config.py` | 配置加载 | YAML + `${ENV}` 环境变量注入；API Key 只存 env；输出约束（必填字段/类型/分值域）可配 |
| `src/core/parser.py` | 强约束输出解析 | 四级降级策略：json → fence → scan → regex；字段/类型/分值域校验；`_meta.parsed_by` 记录解析层级 |
| `src/core/runner.py` | 批量执行引擎 | 线程池并发；jsonl 实时落盘 + case_id 断点续跑；成功率/解析率/延迟 P95/Token/成本汇总 |
| `src/core/schema.py` | 数据结构 | EvalCase / ModelResponse / EvalResult / RunSummary，全部可序列化 |
| `src/datasets/loader.py` | 测试集加载 | jsonl / json / csv 统一归一化为 EvalCase，跨文件 case_id 去重 |
| `scripts/run_eval.py` | CLI 入口 | 多模型串行对比、--mock 离线冒烟、--limit 限量、--no-resume 全量重跑 |

## 2. 为什么这样设计

- **不绑定厂商 SDK**：直接打 `/chat/completions`，OpenAI / Qwen(compatible-mode) / GLM(paas v4) 一套代码通吃，换模型只改 YAML。
- **失败不中断批量任务**：单条用例失败只写 `error` 字段，不抛异常扩散，保证 1000 条跑测不会因为一条超时前功尽弃。
- **断点续跑**：每条结果即时 append 到 jsonl，重跑按 case_id 跳过成功项，进程被杀/限流中断后可直接续跑。
- **解析率可量化**：`_meta.parsed_by` 记录每条输出是靠哪级策略救回来的，后续能直接统计「哪类 prompt 容易诱导模型输出失控」。
- **Mock 模式**：无 Key 也能跑通全链路，用于 CI 与演示；Mock 会故意掺入约 1/7 的脏输出（带代码围栏），验证解析容错。

## 3. 运行方式

```bash
pip install -r requirements.txt
cp .env.example .env          # 填入真实 API Key（.env 已被 gitignore 排除）

python scripts/run_eval.py --mock                       # 离线冒烟，零消耗
python scripts/run_eval.py --model qwen-max             # 真实跑测
python scripts/run_eval.py --model qwen-max glm-4       # 多模型对比
python scripts/run_eval.py --model qwen-max --limit 20  # 限量试跑
python tests/test_engine.py                             # 引擎自检 21 项
```
