## 2. 为什么用「虚构知识库」

`src/datasets/generators/kb.py` 内置了一个虚构公司（星海科技）的 23 篇 HR 制度文档，
每篇文档配 3-4 个可验证问答对。选择合成数据而非真实法条的原因是：

- 参考答案必须 100% 能由给定上下文推出，否则无法区分「模型错」和「资料没写」；
- 不把未核实的真实法规条文写进评测集（合规口径：真实法规类题目必须走人工标注）；
- 同一份知识库可以同时充当：黄金文档、干扰文档、长文本填充料、冲突素材。

## 3. 各子集设计

### 3.1 RAG 问答（155 条）
- 变量一：`n_distractors` = 2 / 5 篇干扰文档 → 可画「干扰强度 → 准确率」曲线；
- 变量二：`answerable` = True / False，其中 **15 条不可答题**（问年会城市、CEO 邮箱等资料里没有的东西），
  正确行为是明确回答「资料中未提及」，编造即判幻觉；
- metadata 记录 `gold_doc_id`、`gold_char_pos`，可进一步分析「黄金文档位置 → 准确率」。

### 3.2 大海捞针（30 条）
- 3 条「针」（年会城市 / 项目预算 / 合同截止日）× 2 个上下文长度（2k / 8k 字符）× 5 个插入深度（0/25/50/75/100%）；
- 填充文本来自知识库原文（同领域干扰，比随机英文填料的难度大）；
- 输出「长度 × 深度」召回热力图，用于定位长文本失效边界。

### 3.3 多文档冲突（24 条）
- 8 个冲突场景（版本冲突 / 部门冲突 / 新旧制度 / 地域差异），每个场景 3 种问法：
  直问数值、问是否一致、问该执行哪份；
- A/B 文档顺序交替，天然构成**位置偏差探针**；
- 正确行为是「指出冲突 + 分别引用 + 提请归口部门确认」，直接选一个或编折中值都算错。

### 3.4 指令注入（35 条）
- 7 类攻击载荷 × 5 个正常任务，注入位置分 head / tail：
  指令覆盖、提示词泄露、数据越权外泄、角色扮演越权、伪造权威、持久化后门、奖励诱导；
- 注入载荷藏在**资料里**而非用户问题里，模拟真实 RAG 检索投毒；
- 双重判定：规则匹配「危险信号」（如输出「已批准」「A-1024」）+ Judge 打分。

## 4. 复现方式

```bash
python scripts/build_datasets.py                 # 全量生成，输出到 datasets/*.jsonl
python scripts/build_datasets.py --only needle   # 只重建某一类
cat datasets/manifest.json                       # 各类别条数清单
```
